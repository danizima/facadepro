# ФАСАД.PRO — сайт и рабочая панель, версия 10.2

Сайт компании с серверным приёмом заявок, приватными вложениями, запросом КП, защищённой панелью и добровольной статистикой. Интерфейс на HTML/CSS/JavaScript; сервер на Node.js 24, SQLite; Python 3 используется для генерации страниц, персональных PDF и отправки SMTP. Внешних npm-зависимостей нет.

### Автоматические выпуски

После однократной установки deploy/setup-autodeploy.py на существующем сервере таймер проверяет main каждые пять минут. Установка начинается только для точного коммита, успешно прошедшего push-проверку .github/workflows/release.yml в этом репозитории. Проверки PR, другого репозитория или другого коммита не подходят. Неуспешный выпуск не повторяется автоматически до появления исправленного коммита.

Доступ к приватным ключам SSH и секретам GitHub для этого варианта не требуется: сервер получает опубликованный код и результат проверки по HTTPS. Репозиторий должен оставаться публичным. Право изменять main фактически даёт право выпускать приложение. Автообновление использует установленный от root скрипт обновления, сохраняющий том, ключи и учётные записи; Caddy и шлюз Timeweb не перенастраиваются. Новые версии самого механизма обновления требуют повторного запуска установщика.

Статус на сервере: /var/lib/facadepro-deploy/status.json. Журнал: journalctl -u facadepro-deploy.service -n 60 --no-pager. Отключение: systemctl disable --now facadepro-deploy.timer. Таймер не останавливает уже запущенное обновление. Резервные копии находятся в /root/facadepro-backups и автоматически не удаляются.

Перед первым запуском смотрите DEPLOY.md. Публикация исходников в GitHub и успешные проверки сами по себе не подтверждают установку на VPS: первичная команда подключения выполняется в консоли сервера.

### Управление новым содержимым

В разделе «Проекты» откройте объект. Фотоотчёты по умолчанию создаются черновиками; заполните период, дату, подписи и добавьте фото. Отметка «Публиковать» и сохранение проекта выводят отчёт на сайт. Предпросмотр показывает подготовленную страницу без публикации; интерактивные сценарии в защищённом окне предпросмотра отключены. Для пояснений выберите фотографию и нажмите на нужную точку.

Раздел «Подборки по ссылке» создаёт адрес, доступный любому обладателю ссылки. Он исключён из индексации, но не защищён паролем: не добавляйте конфиденциальные данные. Скрытые проекты автоматически исчезают и из существующих подборок. PDF содержит выбранные опубликованные проекты и контакты менеджера. Ссылку можно закрыть; срок действия — до 365 дней.

В разделе «Уведомления» заполните SMTP и/или токен Telegram-бота с Chat ID. Сначала сохраните настройки, затем используйте кнопки проверки. До подключения реальных каналов заявки сохраняются в панели. Старые переменные окружения SMTP действуют до первого сохранения новых настроек.

Пароль SMTP и токен Telegram шифруются в базе AES-256-GCM ключом, производным от /data/secret, и не возвращаются в интерфейс. Пустое поле сохраняет прежний секрет; удаление — отдельной отметкой. Резервная копия обязательно должна включать secret вместе с базой. При изменении адреса менеджера или чата ожидающие уведомления перенаправляются на новый адрес; подтверждения посетителям сохраняют своих получателей.

Напоминания отправляются с 09:00 до 19:00 по выбранному часовому поясу, не чаще одного сообщения каждого типа на заявку и канал за день. По умолчанию они отключены. Закрытые заявки, договоры и устаревшие напоминания исключены. В Telegram передаются номер заявки, ответственный и ссылка на панель.

### Обновление существующего сервера

Скрипт deploy/update-timeweb.py принимает полный SHA этого выпуска. Он проверяет существующую установку, сохраняет конфигурацию, собирает образ, кратко останавливает только приложение для согласованной копии /data, запускает новую версию и проверяет её по HTTPS. При ошибке возвращает прежний код и образ, сохраняя текущие данные. Работающий Caddy и настройки шлюза не изменяются. Подробности — DEPLOY.md.

## Возможности предыдущей версии сохранены

1. **Заявки с файлами:** серверная проверка полей, до 5 вложений, не больше 10 МБ на файл и 25 МБ суммарно. После записи в базу посетитель получает номер. Повтор отправки с теми же данными не создаёт дубль.
2. **Подробные кейсы:** музейно-театральный комплекс, ресторан и ЖК «Брусника». Задача, особенности, решение, подтверждённый объём участия. У ресторана — сравнение этапов «каркас / готовое здание»; фотографии разных этапов, не совмещённые технические обмеры.
3. **Раздел для генподрядчиков:** ресурсы команды, форматы сотрудничества, исходные данные для расчёта, портфолио PDF, контакты и запрос подтверждающих документов. Сканы СРО и лицензии не опубликованы, так как отдельно не предоставлены.
4. **Запрос КП:** отдельная форма с площадью, системой, высотой, сроками, желаемой датой получения предложения и документацией. Автоматический расчёт цены не заявляется.
5. **Панель `/admin/`:** заявки, поиск и фильтры, статусы, заметки, приватное скачивание вложений; добавление и редактирование проектов, загрузка и порядок фото, скрытие и удаление объектов; контакты и слоган; смена пароля. Публикация создаёт реальные HTML-страницы на сервере. Конкурирующие сохранения с устаревшей версией отклоняются.
6. **Статистика:** просмотры, интерес к услугам, начало и этапы формы, скачивание портфолио и переходы к телефону/email. Учитывается только с разрешения посетителя. Заявки считаются независимо от разрешения. Показываются страницы, предшествовавшие заявке, источники и обращения по дням.

Первый экран использует слоган «Фасады любой сложности». Портфолио для скачивания — предоставленный файл «Портфолио_ФАСАД_PRO_2026.pdf», версия 3.

## Просмотр

Требуются Node.js **24.14+**, Python **3.10+** и зависимости для PDF. В Dockerfile они устанавливаются автоматически. Для запуска без Docker:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
PATH="$PWD/.venv/bin:$PATH" npm start
```

Для Ubuntu/Debian можно вместо виртуального окружения установить системные пакеты `python3-reportlab` и `python3-pil`, затем выполнить `npm start`. Сервер вызывает `python3` из PATH.

Сайт: http://localhost:4173/. Сервер создаёт рабочий каталог `data/`. Не публикуйте его как статические файлы и не добавляйте в git.

Создайте пользователя в отдельном терминале:

```sh
npm run admin:create -- admin
```

Команда один раз выдаёт случайный пароль. Сохраните его в менеджере паролей; пароль не записывается в исходники. Повторное создание существующего пользователя запрещено. Явный сброс: `node scripts/create-admin.mjs admin --reset`.

В комплекте есть два автономных файла:

- **Фасад_PRO_предпросмотр.html** — 30 публичных страниц, исходное портфолио PDF и новые интерактивные разделы. Персональная подборка открывается в печатном виде: выберите «Сохранить как PDF» в диалоге печати. Карта улиц требует размещённого сайта, метки и фильтры доступны автономно. В этом файле нет сервера; форма честно работает как подготовка письма с ручным добавлением вложений.
- **Фасад_PRO_панель_демо.html** — интерактивная демонстрация панели с тремя явно отмеченными примерными заявками, сотрудниками и датами напоминаний. Вход и сеть не нужны; изменения живут только до обновления файла. Реальные пароли в демонстрацию вводить не нужно.

Рабочую серверную версию запускают из проекта в ZIP. Демонстрационные файлы не заменяют сервер.

## Почта и обработка обращений

Каждая заявка сначала сохраняется в SQLite вместе с метаданными файлов. Далее уведомление менеджеру и, если указан email, подтверждение посетителю помещаются в очередь.

SMTP настраивается в разделе «Уведомления» или первоначально через переменные окружения из `.env.example`. Без SMTP заявки доступны в журнале, письма остаются в очереди; панель показывает это явно. Поддерживаются TLS на 465 и обязательный STARTTLS на 587 с проверкой сертификата. Сохранённые через панель секреты шифруются в базе и не возвращаются браузеру. Файлы не рассылаются вложениями: менеджер получает ссылку на защищённую панель.

Почтовая очередь повторяет неудачные попытки до 5 раз с увеличением интервала; затем сотрудник может повторить отправку из карточки. Успех означает принятие письма SMTP-сервером, а не прочтение получателем. При аварии между отправкой и отметкой в базе повтор письма теоретически возможен; Message-ID сохраняется.

## Данные и защита

- Сотрудники входят по логину и паролю. Пароли хранятся как scrypt-хеши; сессии — как хеши случайных токенов, срок 8 часов.
- В production cookie — HttpOnly, Secure, SameSite=Strict; изменение данных требует корректного Origin и CSRF-токена.
- Есть ограничения частоты входов, заявок и событий, проверка размеров и сигнатур вложений, защита от выхода за пределы каталогов и экранирование редактируемого содержимого.
- Приватные вложения доступны только через авторизованный маршрут и выдаются как скачиваемые файлы. Антивирусная проверка не реализована; вложения следует открывать обычными защищёнными рабочими средствами.
- Сами заявки хранятся 180 дней, события статистики 90 дней, журнал действий 365 дней. Очистка выполняется при старте и каждый час. При необходимости другого срока измените реализацию и публичную страницу обработки данных согласованно.
- Статистика не получает содержимое форм и файлов. Идентификатор посещения случайный; текстовые параметры URL и полные внешние адреса не сохраняются.
- Это односерверная конфигурация с SQLite и локальными файлами. Используйте один экземпляр приложения и постоянный диск для `DATA_DIR`. Не запускайте независимые копии с разными дисками за балансировщиком.
