# ФАСАД.PRO — сайт и рабочая панель, версия 5.1

Сайт компании с серверным приёмом заявок, приватными вложениями, запросом КП, защищённой панелью и добровольной статистикой. Интерфейс на HTML/CSS/JavaScript; сервер на Node.js 24, SQLite; Python 3 используется для генерации страниц, персональных PDF и отправки SMTP. Внешних npm-зависимостей нет.

## Новое в версии 5.1 — главный проект и фотохроника

- `/projects/museum.html` — расширенная страница крупнейшего проекта: отдельный первый экран, параметры участия, фотоотчёты по периодам и архивная галерея.
- Три публикации: май и июнь 2025 года, сентябрь 2026 года. Фильтр по году, переходы к периодам, просмотр фотографий на весь экран, клавиатура и горизонтальные жесты.
- На главной — выделенная ссылка на фотохронику. Главные фотографии комплекса и МФК «Бурный» заменены локальными WebP, архивный снимок музея сохранён.
- У каждого внешнего снимка указаны источник и дата публикации. Точная дата съёмки не установлена; общий ход строительства не выдаётся за работы ФАСАД.PRO.
- Исходные ссылки, авторы, разрешение снимков и статус прав: `source/photo-sources.json`. Публичная лицензия на коммерческое использование внешних фото не подтверждена.

### Добавление фотоотчёта

Добавьте запись в `source/museum-reports.json`: уникальный `id`, `year`, `period`, дату публикации `publishedAt` в формате YYYY-MM-DD, `title`, `summary`, `sourceUrl`, `sourceName`, `credit` и массив `photos` с полями `key` и `caption`. Новейшая запись располагается первой. Файлы разместите как `site/assets/<key>.webp`, размеры внесите в `source/image-sizes.json`. Затем запустите `npm run build` и пересоберите образ для обновления Timeweb. Для автономного просмотра: `python3 package-preview.py ../output`.

Фотоотчёты редактируются в исходниках; существующая панель меняет карточки объектов, но не ленту отчётов. Если музей скрыт в панели, его страница и ссылка на фотохронику на главной не публикуются. При обновлении сохраните существующий том `/data`.

## Новое в версии 5.0 — визуальная часть

- Новый первый экран: большая фотография, ручное переключение трёх объектов, две основные кнопки и управление с клавиатуры.
- Портфолио с чередованием крупных карточек. Фильтры перестраивают сетку без пустых мест.
- Страницы объектов: большая обложка, объём и период, последовательность работ, фотографии деталей, подходящие направления и похожие проекты. Тексты берутся из опубликованного содержимого, не добавляя выдуманных результатов.
- Наглядные карточки услуг с фотографиями объектов и формулировками задач заказчика. На страницах услуг — фотография соответствующего проекта.
- Галереи: кнопки, стрелки клавиатуры, листание горизонтальным жестом, полноэкранное окно и открытие фотографий деталей. Для ресторана сравниваются два доступных этапа с готовым зданием; ползунок поддерживает касание, мышь и клавиатуру. Снимки сделаны в разные моменты и не являются точным совмещённым обмером.
- Плавное появление блоков, реакции карточек и кнопок. `prefers-reduced-motion` отключает эффекты; при отсутствии JavaScript содержимое остаётся видимым.
- Мобильная панель «Позвонить / Обсудить объект» с местом под системную область экрана. Она скрывается при открытом меню, диалоге и настройках статистики. На формах и в сборщике PDF панели нет, чтобы оставить место основным действиям.
- Мобильное меню ограничивает фокус открытой навигацией и закрывается по Esc. Изображения имеют размеры для устойчивой вёрстки.

Карта, PDF, подбор решения, заявки и панель сотрудников сохранены. Новый серверный функционал в этот визуальный выпуск не добавляется.

## Возможности версии 4.0

1. **Главная:** три ключевых объекта с ручным переключением, управлением с клавиатуры и переходом к подбору решения. Фотографии взяты из портфолио компании.
2. **Карта проектов:** `map.html`, фильтры по направлению и типу, поиск, карточки и переход к подборке PDF. Начальные метки показывают населённые пункты, а не точные положения зданий. Подложка OpenStreetMap загружается по нажатию; список и фильтры работают без неё. В редакторе проекта можно задать собственную проверенную отметку.
3. **Подборка PDF:** `portfolio.html`, выбор до 20 опубликованных объектов, порядок страниц и получатель. Сервер формирует PDF с фотографиями, описаниями и актуальными контактами. Сборка ограничена двумя одновременными процессами; получатель не сохраняется в базе. Нужны ReportLab и Pillow, шрифты включены в проект.
4. **Подбор решения:** `solutions.html`, пять задач, подходящие направления, связанные кейсы и список исходных данных. Выбранная задача и тип объекта переносятся в заявку; посетитель может изменить выбор.
5. **Работа с заявками:** ответственный сотрудник, следующее действие, дата контакта, фильтр «Мои заявки» и группы «Просрочено / На сегодня / Запланировано / Без даты». Договоры и закрытые заявки исключены из напоминаний. Дата считается по локальному дню сотрудника; счётчик обновляется раз в минуту в открытой панели. Отдельные push-уведомления и письма о сроках не отправляются.

Автоматическое составление коммерческих предложений в этот выпуск не входит. Существующая форма запроса КП сохранена.

## Возможности предыдущей версии сохранены

1. **Заявки с файлами:** серверная проверка полей, до 5 вложений, не больше 10 МБ на файл и 25 МБ суммарно. После записи в базу посетитель получает номер. Повтор отправки с теми же данными не создаёт дубль.
2. **Подробные кейсы:** музейно-театральный комплекс, ресторан и ЖК «Брусника». Задача, особенности, решение, подтверждённый объём участия. У ресторана — сравнение этапов «каркас / готовое здание»; фотографии разных этапов, не совмещённые технические обмеры.
3. **Раздел для генподрядчиков:** ресурсы команды, форматы сотрудничества, исходные данные для расчёта, портфолио PDF, контакты и запрос подтверждающих документов. Сканы СРО и лицензии не опубликованы, так как отдельно не предоставлены.
4. **Запрос КП:** отдельная форма с площадью, системой, высотой, сроками, желаемой датой получения предложения и документацией. Автоматический расчёт цены не заявляется.
5. **Панель `/admin/`:** заявки, поиск и фильтры, статусы, заметки, приватное скачивание вложений; добавление и редактирование проектов, загрузка и порядок фото, скрытие и удаление объектов; контакты и слоган; смена пароля. Публикация создаёт реальные HTML-страницы на сервере. Конкурирующие сохранения с устаревшей версией отклоняются.
6. **Статистика:** просмотры, интерес к услугам, начало и этапы формы, скачивание портфолио и переходы к телефону/email. Учитывается только с разрешения посетителя. Заявки считаются независимо от разрешения. Показываются страницы, предшествовавшие заявке, источники и обращения по дням.

Первый экран использует слоган «Фасады любой сложности». Портфолио для скачивания — предоставленный файл «Портфолио_ФАСАД_PRO_2026.pdf», версия 3.

## Просмотр

Требуются Node.js **24.14+**, Python **3.10+** и зависимости для PDF. В Dockerfile они устанавливаются автоматически. Для запуска без Docker:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
PATH="$PWD/.venv/bin:$PATH" npm start
```

Для Ubuntu/Debian можно вместо виртуального окружения установить системные пакеты `python3-reportlab` и `python3-pil`, затем выполнить `npm start`. Сервер вызывает `python3` из PATH.

Сайт: http://localhost:4173/. Сервер создаёт рабочий каталог `data/`. Не публикуйте его как статические файлы и не добавляйте в git.

Создайте пользователя в отдельном терминале:

```sh
npm run admin:create -- admin
```

Команда один раз выдаёт случайный пароль. Сохраните его в менеджере паролей; пароль не записывается в исходники. Повторное создание существующего пользователя запрещено. Явный сброс: `node scripts/create-admin.mjs admin --reset`.

В комплекте есть два автономных файла:

- **Фасад_PRO_предпросмотр.html** — 30 публичных страниц, исходное портфолио PDF и новые интерактивные разделы. Персональная подборка открывается в печатном виде: выберите «Сохранить как PDF» в диалоге печати. Карта улиц требует размещённого сайта, метки и фильтры доступны автономно. В этом файле нет сервера; форма честно работает как подготовка письма с ручным добавлением вложений.
- **Фасад_PRO_панель_демо.html** — интерактивная демонстрация панели с тремя явно отмеченными примерными заявками, сотрудниками и датами напоминаний. Вход и сеть не нужны; изменения живут только до обновления файла. Реальные пароли в демонстрацию вводить не нужно.

Рабочую серверную версию запускают из проекта в ZIP. Демонстрационные файлы не заменяют сервер.

## Почта и обработка обращений

Каждая заявка сначала сохраняется в SQLite вместе с метаданными файлов. Далее уведомление менеджеру и, если указан email, подтверждение посетителю помещаются в очередь.

SMTP настраивается через переменные окружения из `.env.example`. Без SMTP заявки доступны в журнале, письма остаются в очереди; панель показывает это явно. Поддерживаются TLS на 465 и обязательный STARTTLS на 587 с проверкой сертификата. Учётные данные не сохраняются в базе и не отдаются браузеру. Файлы не рассылаются вложениями: менеджер получает ссылку на защищённую панель.

Почтовая очередь повторяет неудачные попытки до 5 раз с увеличением интервала; затем сотрудник может повторить отправку из карточки. Успех означает принятие письма SMTP-сервером, а не прочтение получателем. При аварии между отправкой и отметкой в базе повтор письма теоретически возможен; Message-ID сохраняется.

## Данные и защита

- Сотрудники входят по логину и паролю. Пароли хранятся как scrypt-хеши; сессии — как хеши случайных токенов, срок 8 часов.
- В production cookie — HttpOnly, Secure, SameSite=Strict; изменение данных требует корректного Origin и CSRF-токена.
- Есть ограничения частоты входов, заявок и событий, проверка размеров и сигнатур вложений, защита от выхода за пределы каталогов и экранирование редактируемого содержимого.
- Приватные вложения доступны только через авторизованный маршрут и выдаются как скачиваемые файлы. Антивирусная проверка не реализована; вложения следует открывать обычными защищёнными рабочими средствами.
- Сами заявки хранятся 180 дней, события статистики 90 дней, журнал действий 365 дней. Очистка выполняется при старте и каждый час. При необходимости другого срока измените реализацию и публичную страницу обработки данных согласованно.
- Статистика не получает содержимое форм и файлов. Идентификатор посещения случайный; текстовые параметры URL и полные внешние адреса не сохраняются.
- Это односерверная конфигурация с SQLite и локальными файлами. Используйте один экземпляр приложения и постоянный диск для `DATA_DIR`. Не запускайте независимые копии с разными дисками за балансировщиком.

## Редактирование исходников

- `source/content.json` — первоначальные проекты, кейсы, контакты и слоган. После первого запуска текущие изменения сотрудников живут в базе; обновление исходного файла не стирает их.
- `source/services.json` — направления услуг.
- `source/solutions.json` — задачи, связанные направления и кейсы.
- `source/image-sizes.json` — размеры исходных фотографий.
- `site/visual5.css`, `site/visual5.js` — оформление и взаимодействия версии 5.0.
- `source/home-v1.html` — исходные блоки главной, используемые генератором.
- `build.py`, `site_sections.py`, `release4.py`, `visual5.py`, `museum.py` — генератор публичных страниц.
- `site/*.css`, `site/app.js`, `site/public.js`, `site/request.js` — публичный интерфейс.
- `site/admin/` — интерфейс панели.
- `backend/store.mjs`, `server.mjs` — база, API, публикация, файлы и очередь.
- `backend/mail.py` — SMTP с TLS.
- `backend/followups.mjs` — сотрудники, даты и напоминания.
- `backend/portfolio.mjs`, `backend/portfolio.py`, `backend/fonts/` — создание PDF.
- `site/vendor/leaflet/`, `THIRD_PARTY.md` — карта и лицензии компонентов.
- `scripts/create-admin.mjs` — выдача / сброс учётной записи.
- `tests/integration.mjs` — проверка серверных сценариев на временной базе и локальном тестовом SMTP.

```sh
npm run build
npm run check
npm test
python3 package-preview.py /путь/к/результатам
```

Выходной каталог должен находиться вне проекта. Упаковщик включает только исходники и публичные материалы, исключая базу, вложения заявок, пароли, `.env`, временные страницы и данные предпросмотра.

При смене домена измените `PUBLIC_URL`, адреса canonical/OG/sitemap в `build.py` и `site/robots.txt`. Исходное полное портфолио — самостоятельный документ: изменение контактов в панели не меняет его содержимое. Новые персональные PDF используют актуальные контакты из базы.

## Проверка и публикация

Проверены серверные сценарии: запись и повтор заявки, запрещённые файлы, приватное скачивание, вход, CSRF, версии записей, статусы, публикация контента, загрузка фото, сохранность после перезапуска, статистика, SMTP и удаление заявки с файлами. Дополнительно проверены назначение сотрудника, допустимость дат, фильтры сроков, сохранность новых полей после перезапуска, создание PDF и исключение скрытых проектов. Проверка писем выполнялась только на локальном тестовом сервере; реальные письма сотрудникам и заказчикам не отправлялись.

Развёртывание в Timeweb и подключение реальной почты ещё не выполнялись. Инструкция — в `DEPLOY.md`. Docker-контейнер в текущей среде не собирался; приложение проверено напрямую на Node.js 24 / Python 3.12.
