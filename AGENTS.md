# Фасад.PRO: разработка и обычные выпуски

Репозиторий `danizima/facadepro`, ветка `main`, рабочий сайт `https://facadepro.ru`.
Сайт работает на VPS `193.124.47.248` в `/opt/facadepro`.

Когда пользователь поручил подготовить и опубликовать выпуск, выполнить работу
и проверки, опубликовать проверенный коммит в `main`, дождаться успешного push CI
`.github/workflows/release.yml` именно для этого SHA. Повторное разрешение на
порученный выпуск не запрашивать.

Уже установленный `facadepro-deploy.timer` самостоятельно обновляет приложение
после CI. Для обычного выпуска новая команда через Timeweb не нужна. Проверять
`/healthz`, ожидаемую версию, рабочие страницы и соответствие активов коммиту;
успешный GitHub CI сам по себе не подтверждает установку VPS. При задержке читать
состояние и журнал, а не переустанавливать сайт. Правила подтверждения внешних
инструментов этим файлом не отменяются.

Публичные HTML и bundles генерируются `npm run build`. Менять источники Python,
`source/`, JS и CSS; затем пересобирать страницы. Номер версии находится в
`package.json`, сведения о выпуске — в `source/releases.json` и README.
Обязательные проверки: `npm run check`, `npm run build`, `npm test` и браузерный
набор `node tests/browser.mjs` с настроенным Playwright/Chromium. CI также
проверяет Docker-образ. Тестовые заявки и учётные записи создаются только в
изолированном локальном `DATA_DIR`, без отправки рабочих уведомлений.

Сохранять постоянный том, заявки, вложения, пароли, secret, настройки и
внутренние расчёты. Секреты не включать в Git или сообщения. Не менять Caddy,
DNS, шлюз Timeweb или соседние приложения при обычном выпуске.
