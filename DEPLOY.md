## Первоначальная настройка: включить автообновление

В консоли существующего VPS от root скачайте deploy/setup-autodeploy.py из закреплённого коммита выпуска и запустите его с тем же полным SHA. Точная готовая команда выдаётся вместе с выпуском. Установщик не содержит паролей и не требует переноса SSH-ключей в GitHub.

Он устанавливает два служебных скрипта в /usr/local/lib/facadepro и таймер facadepro-deploy.timer. Первая проверка начинается в фоне, последующие — каждые пять минут. Сообщение «Автообновление включено» означает настройку таймера. Установку версии подтверждает сообщение «Установлен и проверен выпуск» в журнале:

    journalctl -u facadepro-deploy.service -n 60 --no-pager

Если проверки GitHub ещё идут, сервер ждёт. Если проверки завершились ошибкой, сайт продолжает работать на прежнем выпуске. После успешных проверок создаётся согласованная резервная копия, обновляется приложение и проверяется HTTPS. Ошибка установки вызывает возврат прежнего кода и образа; база не откатывается, чтобы не потерять обращения. Проверяйте итоговый журнал: неудачный автоматический откат сообщается явно.

Для временного отключения будущих обновлений:

    systemctl disable --now facadepro-deploy.timer

Для включения:

    systemctl enable --now facadepro-deploy.timer

Состояние последней попытки хранится в /var/lib/facadepro-deploy/status.json. Неуспешный коммит повторно не устанавливается; исправление выпуска публикуется новым коммитом. Копии автоматически не удаляются: контролируйте свободное место и переносите нужные копии на отдельный диск. Сохраните /data целиком, включая materials, SQLite и secret.

После установки откройте /compare.html, форму звонка внизу главной и раздел панели «Видео, отзывы, документы». Почта и Telegram используют сохранённые настройки версии 6.0. Реальные видеокейсы, отзывы и документы добавляются через панель; демоматериалы не публикуются.

## Что подготовить

- Сервер с Docker / Compose, либо приложение с поддержкой постоянного диска и единственного экземпляра.
- Постоянный диск, смонтированный в `/data`.
- HTTPS-домен; для этого проекта — `facadepro.ru`.
- SMTP-учётную запись для писем от сайта и адрес получателя заявок.

Файлы проекта не содержат доступов к Timeweb или почте. Пароли введите в настройках размещения / локальном `.env` на сервере, не в исходном коде.

## Docker Compose на сервере

1. Распакуйте проект в отдельный каталог.
2. Скопируйте `.env.example` в `.env` и заполните `PUBLIC_URL`, SMTP и `LEAD_TO`. Ограничьте права файла: `chmod 600 .env`.
3. Запустите:

```sh
docker compose up -d --build
```

Контейнер запускается от непривилегированного пользователя. Порт 8080 доступен только локально серверу; постоянный том называется `facadepro_data` с префиксом проекта Compose.

4. Настройте HTTPS-прокси в существующей панели сервера. Фрагмент маршрута находится в `nginx.conf`; не заменяйте им всю действующую конфигурацию. Прокси направляет запросы на `127.0.0.1:8080`. Внешний HTTP должен перенаправляться на HTTPS.
5. Создайте сотрудника:

```sh
docker compose exec app node scripts/create-admin.mjs admin
```

Сохраните выданный пароль. Панель: `https://facadepro.ru/admin/`.

6. При необходимости создайте остальных сотрудников той же командой с другим логином. Эти логины появятся в поле «Ответственный».

7. Отправьте собственную проверочную заявку с небольшим файлом. Убедитесь, что она видна в панели, файл скачивается после входа, письмо поступает на согласованный адрес. Назначьте ответственного, следующее действие и дату контакта. После перезапуска контейнера заявка и эти поля должны остаться. Проверьте сборку персонального PDF, переход из подбора решения в форму и фильтры карты.

Если домен другой, измените `PUBLIC_URL`, метаданные и sitemap. При переносе DNS сохраните почтовые записи MX/SPF/DKIM/DMARC. Настройку отправителя SMTP согласуйте с используемой почтой.

## Обслуживание данных в версии 13.0

При `NODE_ENV=production` включено ежедневное локальное резервирование в `DATA_DIR/backups`. Настройки: `BACKUP_ENABLED=true`, `BACKUP_INTERVAL_HOURS=24`, `BACKUP_MAX_COPIES=14`, `BACKUP_RETENTION_DAYS=14`. Копии приватны и не обслуживаются HTTP. Контроль состояния — авторизованный GET `/api/admin/maintenance`.

```bash
DATA_DIR=/data node scripts/backup-data.mjs
node scripts/restore-data.mjs --verify /data/backups/ИМЯ
node scripts/restore-data.mjs /data/backups/ИМЯ --to-new-directory /data-restored
```

Восстановление отказывается перезаписывать существующий каталог, не запускает приложение и не меняет текущую конфигурацию. Перед переключением остановленного приложения на восстановленные данные проверьте приватный `runtime-config.json` и параметры запуска. Храните копию вне сервера: локальные копии не защищают от потери диска/VDS. Резервирование диска у Timeweb — отдельная платная настройка, её фактическое включение проверяется в панели провайдера.
