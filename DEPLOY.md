# Размещение ФАСАД.PRO в Timeweb

## Обновление действующего facadepro.ru до 6.0

На действующем VPS сайт установлен в /opt/facadepro, HTTPS обслуживает существующий Caddy. Для этого сервера используйте deploy/update-timeweb.py из конкретного опубликованного коммита. Запуск от root: python3 /root/facadepro-update-v6.py ПОЛНЫЙ_SHA_ВЫПУСКА. Скачайте скрипт из того же коммита; готовая команда предоставляется вместе с выпуском.

Скрипт требует чистую ветку main, проверяет происхождение репозитория и постоянный том, сохраняет прежний коммит и образ. Сборка проходит при работающем сайте. Затем приложение ненадолго останавливается для согласованной резервной копии базы, файлов и ключа шифрования в /root/facadepro-backups. После запуска проверяются версия 6.0.0 по /healthz, HTTPS, главная, музей и панель. Учётные записи и пароль сохраняются.

При ошибке скрипт возвращает прежний код и образ. Данные автоматически не откатываются, чтобы не потерять новые обращения; миграции 6.0 добавляют таблицы и поля. Если восстановление приложения не подтверждено, скрипт сообщает это и путь к резервным материалам. Не запускайте старый первичный установщик повторно и не удаляйте постоянный том.

После сообщения «ГОТОВО» откройте /admin/ → «Уведомления», введите SMTP и/или Telegram, сохраните и отправьте тест. Пароли вводятся только в панели, не в GitHub. Проверьте получение сообщения. В «Проекты» доступны фотоотчёты и пояснения; «Подборки по ссылке» и «Как работаем» вынесены в меню.

Ниже — инструкция для новой установки. К действующему серверу применяйте порядок обновления выше.

Версия 6.0 включает сервер, базу, вложения и генератор персональных PDF. Простого размещения папки `site/` недостаточно для заявок и панели.

## Что подготовить

- Сервер с Docker / Compose, либо приложение с поддержкой постоянного диска и единственного экземпляра.
- Постоянный диск, смонтированный в `/data`.
- HTTPS-домен; для этого проекта — `facadepro.ru`.
- SMTP-учётную запись для писем от сайта и адрес получателя заявок.

Файлы проекта не содержат доступов к Timeweb или почте. Пароли введите в настройках размещения / локальном `.env` на сервере, не в исходном коде.

## Docker Compose на сервере

1. Распакуйте проект в отдельный каталог.
2. Скопируйте `.env.example` в `.env` и заполните `PUBLIC_URL`, SMTP и `LEAD_TO`. Ограничьте права файла: `chmod 600 .env`.
3. Запустите:

```sh
docker compose up -d --build
```

Контейнер запускается от непривилегированного пользователя. Порт 8080 доступен только локально серверу; постоянный том называется `facadepro_data` с префиксом проекта Compose.

4. Настройте HTTPS-прокси в существующей панели сервера. Фрагмент маршрута находится в `nginx.conf`; не заменяйте им всю действующую конфигурацию. Прокси направляет запросы на `127.0.0.1:8080`. Внешний HTTP должен перенаправляться на HTTPS.
5. Создайте сотрудника:

```sh
docker compose exec app node scripts/create-admin.mjs admin
```

Сохраните выданный пароль. Панель: `https://facadepro.ru/admin/`.

6. При необходимости создайте остальных сотрудников той же командой с другим логином. Эти логины появятся в поле «Ответственный».

7. Отправьте собственную проверочную заявку с небольшим файлом. Убедитесь, что она видна в панели, файл скачивается после входа, письмо поступает на согласованный адрес. Назначьте ответственного, следующее действие и дату контакта. После перезапуска контейнера заявка и эти поля должны остаться. Проверьте сборку персонального PDF, переход из подбора решения в форму и фильтры карты.

Если домен другой, измените `PUBLIC_URL`, метаданные и sitemap. При переносе DNS сохраните почтовые записи MX/SPF/DKIM/DMARC. Настройку отправителя SMTP согласуйте с используемой почтой.

## App Platform

Dockerfile также можно использовать для сборки приложения. До запуска обеспечьте постоянный диск для `/data` и один экземпляр сервиса. Health check: `/healthz`; порт: `8080`. Секреты передаются как переменные окружения. Если выбранный способ размещения не сохраняет `/data` между развёртываниями, используйте сервер с постоянным томом либо замените SQLite/файлы на внешнюю базу и объектное хранилище до запуска.

## Обновление и резервные копии

При обновлении 4 → 5 пересоберите образ. В комплект добавлены `visual5.py`, `site/visual5.css`, `site/visual5.js` и `source/image-sizes.json`; Dockerfile уже включает их. Структура базы в этом визуальном выпуске не меняется. После запуска проверьте главную, галерею объекта, мобильное меню и отправку проверочной заявки.


Перед обновлением версии 3 → 4 сделайте резервную копию `/data`. При первом запуске сервер добавит три поля планирования контактов и индекс; существующие заявки, статусы, пароли и файлы сохраняются. Повторный запуск безопасен для уже добавленных полей. Направления и начальные метки для исходных проектов дополняются без замены пользовательских текстов; если адрес исходного проекта изменён, координаты нужно указать вручную.

В новой версии Dockerfile устанавливает `python3-reportlab` и `python3-pil`. При обновлении обязательно пересоберите образ. Для запуска вне Docker установите зависимости из `requirements.txt`, как описано в README.

Обновляйте образ без удаления тома. **Не выполняйте `docker compose down -v`** для рабочего проекта: параметр `-v` удаляет данные.

Резервная копия должна включать весь `/data`: базу, вложения, фотографии, секрет подписи и опубликованное содержимое. Для простой согласованной копии остановите приложение на время копирования тома или используйте согласованный механизм снимков сервера. Храните копии отдельно от рабочего диска, с ограниченным доступом, и проверяйте восстановление.

После восстановления проверьте вход, заявки, приватные файлы и изображения проектов. Новые персональные PDF используют актуальные контакты. Обновление контактов в панели не редактирует исходный опубликованный PDF портфолио — при изменении документа замените `site/downloads/portfolio.pdf`.


## Карта и напоминания

Начальные метки объединены по населённым пунктам; точные координаты объектов не заявляются. Подложка OpenStreetMap запрашивается браузером только после нажатия кнопки. Сохраняйте атрибуцию и ограничения провайдера, не добавляйте массовую загрузку или офлайн-кэш плиток. При недоступной подложке остаются карточки и фильтры.

Напоминания отображаются в панели по локальному календарному дню сотрудника. Даты хранятся без времени. Для напоминания необходимо указать следующее действие. В версии 6.0 почтовые и Telegram-напоминания включаются отдельно в разделе «Уведомления», где задаётся часовой пояс и интервал для новых заявок.
